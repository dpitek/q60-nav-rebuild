Deploy via:


**What's new in this Qt build vs yesterday:**
- Plugin now resolves `emgdHmiMapPixmap` (6-arg signature) at platformInit
- After `createNativeWindow`, maps the pixmap memory and stores the CPU vaddr
- `presentBuffer` (called by Qt after each `eglSwapBuffers`) does `glFinish` + `glReadPixels(0, 0, w, h, GL_RGBA, GL_UNSIGNED_BYTE, vaddr)` — copies the GL render into the scanout-readable memory.

**Trade-off:** glReadPixels is slow (CPU readback per frame, ~1.5 MB at 800x480 ARGB). Fine for proof-of-concept, terrible for production. Long-term fix: custom Qt platform plugin that renders into a QImage backed by pixmap memory directly (drawbuf-style — no GL).

**Recommended order:**
1. Boot spike 7 first (smaller surface area, easier to debug)
2. If spike 7 shows visible color bars → Plan B''' confirmed, try Qt next
3. If spike 7 also invisible → there's a deeper issue; don't bother with Qt
